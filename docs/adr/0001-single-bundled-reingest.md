# 匯入端的改動一次重匯，不逐項驗證

狀態：accepted（2026-11-18）

台新知識庫要優化回答品質，有幾項改動需要全量重匯：語言改成繁體中文、改用信用卡領域的實體類型、加上卡片標籤（檔名與 chunk 標頭），之後可能再加上新的切塊方式。用 Qwen 全量匯入花了 24–44 小時，Gemma 4 還沒有實測過。我們決定把這些改動放進同一次重匯，只比較重匯前後的整體 eval 結果，不分開量每一項各自的效果。

## Considered Options

- **每項改動各重匯一次**：可以知道每一項的效果，但要花好幾天 GPU 時間。
- **只在查詢端把語言改成中文**：圖譜描述仍是英文，兩邊語言不一致。結果變差時，分不出是中文沒用，還是語言不一致造成的。
- **用約 25 份文件建兩個小知識庫，只差語言**：比較公平，但使用者決定直接採用中文，不做這個比較。

## Consequences

- eval 結果變好或變差時，無法判斷是哪一項造成的。如果之後要追究，只能在副本上逐項還原再重匯。
- 重匯前，切塊方式要先依歸因結果定案，因為重匯只做一次。
- 2026-11-19 補充：依標題切塊與 embedding 換成 Qwen3-Embedding-4B 也放進這次重匯（`.scratch/rag-optimization/spec.md`）。換 embedding 本身只要重算向量、不用重新抽實體，但重匯時一起做，可以省掉之後另外重算一次約 12.7 小時。
