# 01: 調查查詢時抽關鍵字的 JSON 不合法、查詢直接失敗

**What to build:** 這張是調查票，不改程式。要回答：查詢時 LLM 抽關鍵字輸出不合法的 JSON 導致查詢失敗，發生頻率多高、能不能從根本上避免，以及修法會不會改變其他查詢的結果。調查結果決定要不要再開實作票。

**Blocked by:** None (can start immediately)

**Status:** ready-for-agent

- [ ] 找出 LightRAG 1.4.16 抽關鍵字的 prompt、解析 JSON 的程式碼位置，以及解析失敗時的行為（直接讓查詢失敗、重試，或改用別的方式）。
- [ ] 查 `mlx_lm.server`（pipx 安裝的 mlx-lm 0.32.0）支不支援限制輸出格式（例如 OpenAI 的 `response_format` 或 JSON schema）。要看原始碼，不能只看文件。
- [ ] 量頻率：用現有的 4B 模型，對 eval 題目和 2026-11-01 方案 C 實驗的子問題，只跑抽關鍵字（不檢索、不生成）各 N 次。N 由調查者決定，要寫出理由。記錄不合法的次數與輸出的樣子。需要啟動 port 8080 的 LLM server。
- [ ] 列出可行的修法與代價，至少比較：限制輸出格式（如果 server 支援）、在 rag_lab 解析失敗時讓錯誤訊息指出原因、換模型。不能只加重試來掩蓋。
- [ ] 結果寫在這張票的「調查結果」段落：事實和推測分開寫，每個結論都要附出處（檔案:行號或 log 路徑）。
