# 02: 下載卡片頁（tracer bullet）

**What to build:** 使用者執行新的下載腳本，就能從信用卡總覽頁找出所有卡片頁，各自列印成 PDF 放進卡片資料夾，原始 HTML 另存在不會被匯入的位置，並得到一份下載清單。這張也建立整支腳本共用的行為，後續的類別都沿用：請求間隔、User-Agent、失敗處理、再次執行時略過、網址前綴與 Chrome 路徑的替換。

**Blocked by:** 01（新腳本要用 01 合併進 main 的假 LibreOffice 夾具與既有下載腳本的慣例）

**Status:** ready-for-agent

- [ ] 腳本從總覽頁取出卡片頁連結並去除重複。找到的數量不是 16 時，印出實際數量，但不中止。
- [ ] 每張卡用 headless Chrome 列印原網址成 PDF，使用暫時的使用者資料夾。本地檔名由網址路徑組成，加上類別前綴，整批唯一。
- [ ] 每一頁的原始 HTML 保存在不會被匯入的位置。
- [ ] 下載清單一行一份文件，記錄網址、類別、本地檔名、格式、下載日期、匯入檔案的 SHA-256、原始 HTML 的 SHA-256、結果（已下載、已存在略過、失敗及原因）。
- [ ] 腳本自己發出的每個 HTTP 請求之間至少 2 秒；間隔可以用環境變數調小，只給測試用。請求帶有可辨識的 User-Agent。
- [ ] `www` 網域的網址前綴與 Chrome 路徑可以用環境變數替換。找不到 Chrome 時，那一頁記為失敗，訊息指出環境變數名稱。
- [ ] 單頁失敗時其他頁照常完成，最後列出所有失敗的頁面並以非零碼結束。總覽頁本身失敗時，以非零碼結束並指出是哪一個列表。
- [ ] 再次執行時，已存在的檔案略過並記入清單。
- [ ] 只用標準函式庫；檔頭 docstring 寫明 Chrome 自行載入 CSS 與圖片的請求不受間隔控制。
- [ ] 新增假 Chrome 夾具：接受列印成 PDF 的參數並寫出小 PDF，參數不符時以非零碼結束並印出收到的參數。
- [ ] 以子行程測試上述行為：本機假 HTTP server，只看結束碼、輸出、產生的檔案、清單內容與假 server 收到的請求。請求間隔用假 server 記錄的時間檢查。
- [ ] 下載腳本的測試、主測試套件與既有下載腳本的測試都全綠。
