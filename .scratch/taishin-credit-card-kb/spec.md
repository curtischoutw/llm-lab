# Spec：知識庫改為台新銀行信用卡的權益與規則

## Problem Statement

使用者想用自己的知識庫，問台新銀行信用卡的權益、回饋規則、費用與約定條款。目前的知識庫做不到：

- 知識庫的內容是 3 篇 RAG 論文加 6 份 RAG 主題的文件，和信用卡無關。
- 台新信用卡的內容散在官網的卡片頁、權益說明子頁、文件下載區的 PDF，以及另一個子網域上的刷卡優惠活動頁，約 140 份。沒有任何方法能用一個指令取得這批內容。
- 官網大部分內容是網頁，而 `ingest` 不收 HTML。專案用的 MinerU 解析器也無法解析 HTML。
- 使用者仍然要讓知識庫由多種格式組成，讓 PDF、Word、圖片的解析路徑都被實際用到。官網沒有公開的 PPT、Word、Excel。
- 權益多半有適用期間，而且每年換版。目前沒有地方記錄每份文件是哪一天取得的。
- Richart 卡可以每天切換回饋方案，這是使用者特別想問的主題。目前沒有任何題目可以確認知識庫答得出來。

## Solution

用新的知識庫取代舊的：

- 先把現有的 integration 分支合併到 main，再刪除舊知識庫、它的備份、舊的下載資料與 MinerU 解析輸出。量測紀錄、程式碼與題目檔保留，README 把舊的實測數據標成「前一版知識庫的量測」。
- 新增一支下載腳本。它每次執行時都從官網的四個列表找出網址，下載以下內容：
  - 總覽頁的 16 張卡的卡片頁；
  - 46 個權益說明子頁；
  - 文件下載區的所有 PDF；
  - 進行中的刷卡優惠活動頁。
- 下載腳本依頁面類別決定匯入格式：
  - 卡片頁與活動頁：從原始 HTML 取出主內容區，拿掉官網的 CSS 與 script，再用 headless Chrome 列印成 PDF；
  - 權益說明子頁：同樣取出主內容區，用 LibreOffice 轉成 Word（`.docx`）；
  - 下載區的 PDF 維持原樣；
  - 取幾個活動頁的主視覺圖片當作圖片文件。
- 每一頁的原始 HTML 另外保存。下載清單記錄每份文件的網址、類別、格式、下載日期、SHA-256；活動頁另外記錄活動期間。
- 先匯入 7 份文件，量測耗時與記憶體，再匯入全部文件。
- 寫一份 20 題的新題目檔，其中至少 4 題問切換。用 `eval` 跑五種檢索模式，逐格判讀。
- 查詢設定維持 `QUERY_MAX_TOTAL_TOKENS=12000`、不啟用 rerank，作為這個知識庫的基準。

## Implementation Decisions

用語：本 spec 依 `GLOSSARY.md`。匯入單位叫「文件」，副檔名類別叫「格式」，「知識庫」沒有特別說明時指台新信用卡主知識庫。

### 清理與分支

- 第一張 ticket 開頭先把 `integration/multi-format-documents` 以 `--no-ff` 合併到 main，不 push。之後的工作從 main 開新的 integration 分支。
- 要刪除的路徑：
  - 主知識庫 `WORKING_DIR`，以及 ticket 06 建立的備份；
  - 舊的下載資料：論文、6 份文件、格式驗證文件，以及論文 symlink 資料夾；
  - `PARSER_OUTPUT_DIR` 底下 MinerU 的解析資料夾與 Office 轉檔 PDF。
- 刪除前，先在對話中列出每個路徑與大小，使用者確認後才執行。
- 保留的內容：
  - `output/` 底下的量測紀錄資料夾，以及 `eval_results/`；
  - 所有程式碼、測試、舊的下載腳本、舊題目檔（範例題目檔被測試引用）。
- `.gitignore` 裡已經不存在的路徑規則可以留著，不必清理。

### 下載腳本

- 新增一支獨立的下載腳本，與現有的兩支下載腳本放在一起。只用 Python 標準函式庫，HTML 用標準函式庫的解析器讀取。另外以子行程呼叫兩個外部命令：Chrome 與 LibreOffice。不新增 Python 依賴。
- 網址來源：
  1. 信用卡總覽頁：取出卡片頁連結（路徑形如 `/overview/cgNNN/cardNNN/`），應有 16 筆。
  2. 信用卡權益頁：取出權益說明子頁連結，2026-10-30 是 46 筆。
  3. 文件下載頁（信用卡）：從第 1 頁開始往後翻，直到某一頁沒有新的 PDF 連結為止。目前是 2 頁、約 19 個 PDF。
  4. 刷卡優惠列表：在 `mkpcard` 子網域上，分類 A–I，每類都翻到沒有新連結為止。取出活動詳情頁連結，活動詳情頁在 `mkp` 子網域。
  - 網址去除重複。卡片頁的 5 個分頁在同一份 HTML 裡，所以一張卡只抓一次。
- 類別與格式（固定規則）：

  | 類別 | 來源 | 匯入格式 | 轉檔方式 |
  |---|---|---|---|
  | 卡片 | 卡片頁 | PDF | 取主內容區另存成本機 HTML，headless Chrome 列印 |
  | 權益 | 權益說明子頁 | `.docx` | 取主內容區另存成本機 HTML，LibreOffice 轉成 docx |
  | 下載 | 文件下載區 | PDF | 不轉檔 |
  | 活動 | 活動詳情頁 | PDF | 取主內容區另存成本機 HTML，headless Chrome 列印 |
  | 活動圖片 | 活動詳情頁的主視覺圖片 | 圖片 | 不轉檔，只收支援的圖片格式 |

  - 活動圖片只取依發現順序前 8 個有主視覺圖片的活動頁。主視覺是活動詳情頁 `div.banner-image` 裡的圖片；沒有這個元素就視為沒有主視覺。內容區的第一張圖片是分享圖示，不是主視覺。2026-10-30 的 5 個樣本中有 2 頁沒有主視覺。
- 主內容區與列印前處理：
  - 2026-10-30 實測：直接用 headless Chrome 列印 Richart 卡片頁的原網址，PDF 只有 2 頁、1,074 字，原始 HTML 的可見文字是 36,767 字。卡片頁的 5 個分頁是預設收合的區塊，切換規則在隱藏的彈窗裡，官網的 CSS 讓它們在列印時不顯示。PDF 裡「23:59」與「天天刷」都出現 0 次。
  - 因此：
    - 從原始 HTML 取出主內容區的元素。卡片頁與權益子頁是 `id="centercontainer"`，活動詳情頁是 class 含 `page-content` 的元素。
    - 拿掉其中的 `<script>` 與 `<style>`，包成一份新的 HTML。新 HTML 只帶一段固定的列印用 CSS（圖片寬度與表格框線），並用 `<base href>` 指回原網址，讓相對路徑的圖片可以載入。
    - 這份新 HTML 存在不會被匯入的位置，再交給 Chrome 或 LibreOffice。
    - 找不到主內容區時，那一頁記為失敗，原因寫「找不到主內容區」。
  - 實測結果：
    - 卡片頁：Richart 的 PDF 是 31 頁、34,576 字，「23:59」出現 11 次，沒有 cookie 橫幅與導覽選單。
    - 活動頁：PDF 是 4 頁、3,164 字，整頁可見文字是 3,835 字，差額是導覽選單。
    - 權益子頁：LibreOffice 轉 docx 不受官網 CSS 影響，整頁 11,367 字轉出 11,309 字。取主內容區是為了去掉導覽選單。
  - 列印出來的版面是純 HTML 的排版，不像官網。使用者已同意（2026-10-30）。
- 每個類別放在資料根目錄底下自己的子資料夾，資料根目錄是 `data/` 底下新的一個資料夾。原始 HTML 與下載清單放在不會被匯入的位置：可以是另一個子資料夾，也可以是檔名不屬於支援格式的檔案。
- 本地檔名由網址路徑組成，例如卡片頁用 `cgNNN`、權益子頁用路徑最後兩段、活動用 `WM_` 編號，並加上類別前綴，保證整批唯一。
- 活動過期判斷：從活動詳情頁讀出活動期間。結束日早於下載當天就略過，在清單記為過期。讀不出期間時照樣下載，在清單記為期間不明。
- 下載清單一行一份文件，欄位包括：
  - 網址、類別、本地檔名、格式、下載日期、匯入檔案的 SHA-256、原始 HTML 的 SHA-256（網頁類才有）；
  - 活動期間（活動類才有）；
  - 結果：已下載、已存在略過、過期略過、失敗及原因。
  - SHA-256 只記錄，不和上一次比對。
- 請求間隔：腳本自己發出的每個 HTTP 請求之間至少 2 秒。間隔可以用環境變數調小，唯一用途是讓測試加速。Chrome 與 LibreOffice 轉檔時，會透過 `<base href>` 自己載入圖片，這些請求不受腳本的間隔控制，這是已知限制。
- 網址前綴：腳本會連到三個網域（`www`、`mkpcard`、`mkp`），每個網域都可以用環境變數換成本機假 server，只給測試用。
- Chrome：預設是 macOS 上 Google Chrome 的標準安裝路徑，可以用環境變數覆寫。找不到時，那一頁記為失敗，訊息指出環境變數名稱。列印時使用暫時的使用者資料夾，不用使用者自己的 Chrome profile。
- LibreOffice：沿用 RAG-Anything 的找法，在 PATH 上依序找 `libreoffice`、`soffice`。
- 失敗處理：
  - 單頁失敗（HTTP 錯誤、網路錯誤、轉檔失敗、檔案系統錯誤）時，記下原因，其他頁照常處理，最後列出所有失敗的頁面並以非零碼結束。
  - 列表頁本身失敗時，那一類找不到任何網址，以非零碼結束並指出是哪一個列表。
  - 總覽頁找到的卡片數不是 16 時不中止，在輸出中印出實際數量，提醒官網可能改版。
- 再次執行：本地檔案已存在就略過，在清單記為已存在。要更新內容時，刪除資料資料夾與知識庫後重新下載、重新匯入。這不在本 spec 實作，只寫進 README。
- 下載的檔案是不可信資料：腳本不執行它們，Chrome 與 LibreOffice 只做轉檔。

### 匯入與實機驗證

- `rag_lab` 不改程式碼。PDF、`.docx`、圖片已經支援，資料夾匯入不遞迴，也會略過不支援的格式。
- 試匯入：7 份文件。
  - 選擇：Richart 卡片頁（PDF）、約定條款（下載區 PDF，23 頁）、2 個權益子頁（`.docx`）、2 個活動頁（PDF）、1 張活動圖片。
  - 用 symlink 放進一個試匯入資料夾後匯入。RAG-Anything 的文件 ID 是解析內容的雜湊，所以全量匯入時這 7 份會被略過。
  - 抽查 MinerU 的內容清單，確認中文沒有變成亂碼。
- 全量匯入：依類別逐一匯入各個子資料夾，順序是卡片、權益、下載、活動、活動圖片。

### 題目檔與驗收

- 新增題目檔，納入版本控管，欄位沿用現有格式：`id`、`question`、`reference`、`type`、`source`。共 20 題。
- 類別寫在 `id` 前綴：

  | 前綴 | 類別 | 至少題數 |

  | `terms-` | 約定條款 | 2 |

## Testing Decisions

- 好的測試只看外部行為：以子行程執行下載腳本，檢查結束碼、stdout／stderr、產生的檔案與下載清單的內容，以及假 server 收到的請求。不 import 腳本的內部函式，不替換腳本裡的資料。
- 唯一的自動測試縫：下載腳本的子行程。
  - 本機假 HTTP server 提供三個網域的假頁面：總覽頁、權益頁、文件下載頁（含分頁）、刷卡優惠列表（含分類與分頁）、卡片頁、權益子頁、活動詳情頁（含活動期間與主視覺圖片），以及 PDF 與圖片檔。
  - 三個網域的網址前綴與 Chrome 路徑，都透過環境變數指到假的版本。
  - 假 Chrome：一支測試夾具，接受 headless 列印成 PDF 的參數，輸入是本機 HTML 檔，寫出一個小 PDF，並把收到的 HTML 內容一起寫進輸出檔，讓測試檢查交給 Chrome 的內容。參數不符時以非零碼結束，並印出收到的參數。
  - 假 LibreOffice：擴充現有夾具，讓它也接受轉成 docx。對其他參數維持嚴格檢查。
- 要涵蓋的行為：
  - 四個列表都會被找到；文件下載頁與活動列表會翻到最後一頁；重複的網址只下載一次。
  - 每個類別產生正確的格式，放在正確的資料夾，檔名唯一；原始 HTML 被保存在不會被匯入的位置。
  - 交給 Chrome 與 LibreOffice 的 HTML 只含主內容區，不含官網的 script、樣式表與主內容區以外的文字；找不到主內容區的頁面記為失敗。
  - 過期活動被略過、期間不明的活動被收進來，兩者都記在清單裡。
  - 活動圖片的數量上限，以及不支援格式的圖片被略過。
  - 下載清單的欄位與內容。
  - 單頁 HTTP 錯誤、轉檔失敗、Chrome 不存在時，其他頁照常完成，最後以非零碼結束並列出失敗的頁面。
  - 列表頁失敗時，以非零碼結束並指出是哪一個列表。
  - 再次執行時，已存在的檔案被略過。
  - 請求帶有可辨識的 User-Agent。
  - 請求之間的間隔不小於設定值。測試把間隔設成很小的值，再用假 server 記錄的請求時間檢查。
- 參考的既有測試：
  - 現有下載腳本的子行程測試：假 server、環境變數換網址前綴、只看結束碼與檔案；
  - 現有的假 LibreOffice 夾具：嚴格檢查參數、用主檔名模擬失敗。
- `rag_lab` 沒有修改，不新增測試。完成時跑完整的主測試套件與兩支既有下載腳本的測試，確認沒有被影響。
- 真實下載、試匯入、全量匯入與 eval 是手動實機驗證，不做成自動測試。結果寫進 ticket 的實作結果與 README。
