# 01: 官網簽帳金融卡卡片頁

**What to build:** 使用者執行台新下載腳本時，除了信用卡，也會下載官網簽帳金融卡專區的 5 張卡片頁：Visa金融卡、元氣Visa金融卡、財富管理Visa金融卡、勞動保障卡、蝴蝶悠遊Debit卡。專區列表上的群組落地頁只有一段 JS 轉址，腳本從轉址目標找到真正的卡片頁（`card01/` 或 `card001/`），用和信用卡卡片頁相同的方式（取主內容區、Chrome 列印）轉成文件。金融卡文件的本地名稱加 `debit_` 前綴，所以和同編號的信用卡卡片頁（cg003、cg008）不撞名。更新模式（`--update`）對這個類別也有效。這張也定下金融卡新類別的命名方式，02、03 照著用（spec：`.scratch/debit-card/spec.md`「下載腳本」，盤點事實見 Further Notes）。

**Blocked by:** 增量更新（`.scratch/incremental-update/`）推上 main 之後才開工，從那時的 main 開分支（spec 外的前置條件，grill Q18）。

**Status:** ready-for-agent

- [ ] 從簽帳金融卡專區列表找到 5 張卡的群組落地頁，依落地頁的轉址目標下載 `card01/` 或 `card001/` 的卡片頁；不執行 JS。
- [ ] 轉址目標的相對網址以落地頁為基準解析；目標不在官網網域、或不在同一個 `payment/cgXXX/` 底下時，當成找不到轉址目標。
- [ ] 落地頁找不到轉址目標或請求失敗時，那一張記成失敗並寫明原因，其他卡照常；更新模式下這次整個類別不判斷下架，已下載的那張不會被搬走。
- [ ] 資料夾與本地名稱照 spec「下載腳本」的類別表：`debit_cards/`、`debit_card_cgXXX_card01`（或 `card001`）；同編號的信用卡卡片頁與金融卡卡片頁同時存在、互不覆寫。下載清單照現有欄位記錄。
- [ ] 更新模式：內容沒變不重寫、主內容區變了才重新轉檔、列表上消失的卡片頁搬到 `_meta/removed/<日期>/`，和信用卡卡片頁相同；列表頁解析出 0 張而本地有檔案時，這次不判斷下架。
- [ ] 測試沿用下載腳本子行程＋假 HTTP server、假 Chrome 的縫，涵蓋 `card01/` 與 `card001/` 兩種轉址、相對與絕對網址、目標不在同一個群組底下、找不到轉址目標時不判斷下架、撞名；現有測試全綠。
- [ ] 下載腳本的模組說明與 README 第 2 節寫明金融卡類別，以及下載資料夾雖然叫 taishin_credit_card、裡面也有金融卡。
