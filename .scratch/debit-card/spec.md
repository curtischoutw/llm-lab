# 金融卡加入台新知識庫

**Status:** ready-for-agent

## Problem Statement

客戶發問時常把金融卡和信用卡搞混：說「Richart 卡」但指的是簽帳金融卡，或拿信用卡才有的權益去問金融卡。目前的台新知識庫只有信用卡，問答系統遇到金融卡的問題時，只能拿信用卡的資料回答，答案可能把兩種卡片的權益、費用、條款混在一起，而且沒有數據說明混得多嚴重。

## Solution

把台新的金融卡（簽帳金融卡與晶片金融卡）資料下載下來，追加匯入現有的台新知識庫，題庫新增一類金融卡題目。匯入前後各跑一次 eval，比對信用卡題目有沒有變差，並逐題列出答案把信用卡和金融卡搞混的句子。這份 spec 只收資料與量測；要不要改回答方式，看量測結果另開 spec。

## User Stories

## Implementation Decisions

### 詞彙

- 依 GLOSSARY：**金融卡** 包含簽帳金融卡（可以刷卡，從存款帳戶扣款）與晶片金融卡（只能提款、轉帳）；**卡片** 是信用卡與金融卡的合稱；**Richart 卡** 只指信用卡「台新 Richart 卡」，Richart 品牌的簽帳金融卡（D 卡、遛狗卡、綠狗卡、白狗卡）要寫出卡名。
- 權益、費用、約定條款都是「某張卡片的」，講到時要說出是信用卡還是金融卡。

### 收錄範圍（grill Q11，2026-11-02 盤點）

- 官網簽帳金融卡專區：
  - 5 張卡的卡片頁：Visa金融卡、元氣Visa金融卡（2018/6/11 起停止受理申請，仍收）、財富管理Visa金融卡、勞動保障卡、蝴蝶悠遊Debit卡。
  - 4 份約定條款 PDF：簽帳金融卡用卡須知、簽帳金融卡權益手冊、勞動保障卡約定事項、悠遊 Debit 卡特別約定條款。約定條款頁上指向悠遊卡公司的外部連結不收。
  - 相關費用說明頁、常見問題 2 頁（申請篇；刷卡消費／跨國提款篇）。
  - ASSUMPTION：專區列表上的「Richart簽帳金融卡」摘要頁也收（它在同一個列表，內容是三款狗卡的名稱、0.5% 回饋與悠遊卡功能）。
- richart.tw：簽帳金融卡頁、信用卡頁，以及這兩頁連到的所有優惠細則頁。簽帳金融卡頁連到 14 則（盤點時）；信用卡頁連到幾則還沒查。
- 存款專區晶片金融卡：介紹頁、卡片介紹、消費扣款與跨國提款，共 3 頁。
- mkpcard 活動不另外收：現有的 209 個活動已在知識庫，其中 61 頁的主內容寫了適用卡別（「台新信用卡／簽帳金融卡」）。
- 估計 30–35 份文件，實數以下載結果為準。

### 下載腳本

- 用現有的台新下載腳本新增金融卡的類別，不另寫腳本（grill Q13）。新類別要接上增量更新的更新模式（比對、下架、搬移），所以實作在增量更新推上 main 之後才開工（grill Q18）。
- 下載到現有下載資料夾底下的新類別資料夾（例如官網金融卡卡片頁、金融卡約定條款與說明頁、Richart、晶片金融卡；資料夾名稱由實作決定，風格與現有的一致）。不改下載資料夾的名稱：對照表以路徑認定文件，改名會讓 311 份文件全部被當成移除再新增。README 寫明資料夾雖然叫 taishin_credit_card，裡面也有金融卡。
- 官網金融卡文件的本地名稱一律加 `debit_` 前綴：官網金融卡的群組編號（cg003、cg008）和已下載的信用卡卡片頁（`card_cg003_…`、`card_cg008_…`）重複。richart.tw 的文件加 `richart_` 前綴，不用 `debit_`：其中的信用卡頁與信用卡的優惠細則不是金融卡，檔名不能寫成金融卡。
- 官網金融卡的群組落地頁只有一段 `location.replace` 轉址，內容在 `card01/` 或 `card001/`（勞動保障卡與蝴蝶悠遊Debit卡是 `card001/`，`card01/` 回 404）。腳本從落地頁的轉址目標取得真正的網址，不執行 JS；找不到轉址目標時記成失敗。
- 轉檔方式：網頁類（官網卡片頁、費用、常見問題、Richart 各頁、晶片金融卡各頁）和信用卡卡片頁相同，取主內容區、拿掉 script 與樣式後用 Chrome 列印；官網頁的主內容區是 `#centercontainer`。richart.tw 的主內容區由實作者從 HTML 判斷（ASSUMPTION，寫進模組說明）。PDF 照原檔存。
- 網域：允許清單加上 `richart.tw`；請求間隔、轉址規則與現有的相同（grill Q15）。richart.tw 沒有 robots.txt（`/robots.txt` 轉址到首頁）。
- 下載清單記錄的欄位與現有的相同。

### 匯入

- 追加匯入現有的台新知識庫，每個新類別資料夾跑一次 `ingest`（會寫進對照表）。不改匯入端的程式。
- 記錄文件數、耗時、GPU 記憶體峰值。匯入期間照之前的做法開 watchdog。

### 題庫與 eval

- 現有 20 題一字不改。新增一類「金融卡」8 題：(a) 混淆、(b) 事實、(c) 否定、(d) 卡別說錯，各 2 題（grill Q5、Q8、Q14）。(d) 至少 1 題用「Richart 卡」這種有歧義的說法發問（grill Q12）。
- 題目由主對話在下載完成後依文件起草，每題附來源文件與期望答案，使用者審過才定案，在跑新基準之前完成。
- 順序（grill Q4、Q17）：下載 → 起草題目、使用者審定 → 新基準 eval（28 題，知識庫還沒有金融卡）→ 匯入金融卡 → 再跑一次 eval（28 題）。兩次都只跑 mix。
- 判讀：和之前相同，兩個判讀者各自評分再比對分歧；答案提到權益或費用卻沒說是哪一種卡片時，最多算 △（grill Q7）；這條規則兩次 eval 的 28 題都套用，包括現有 20 題信用卡題目（grill Q20）。所以新基準的分數不能直接和 2026-11-01 的 mix ✓9 比較，判讀紀錄要寫明這點。另外逐題列出答案裡把信用卡和金融卡搞混的句子，不設門檻（grill Q6）。
- 驗收（grill Q6）：
  - 現有 20 題在 mix 的 ✓ 數，比新基準最多少 1 題（兩次 eval 本身有 1 題左右的起伏）。
  - 匯入後，金融卡四種題型各至少 1 題 ✓。
  - 搞混實例清單、匯入耗時與 GPU 峰值寫進紀錄。

## Testing Decisions

- 好的測試只看外部行為：下載腳本的結束碼、輸出、產生的檔案（類別資料夾、`_meta`、下載清單），不測內部函式。
- 縫：下載腳本的子行程，搭配現有的假 HTTP server、假 Chrome、假 LibreOffice（grill Q16）。不新增其他縫；匯入端不改程式，不加測試。
- 要涵蓋的行為：官網金融卡落地頁的轉址（`card01/` 與 `card001/` 兩種、找不到轉址目標時失敗）；`debit_` 前綴讓同編號的信用卡與金融卡文件不撞名、richart.tw 的文件用 `richart_` 前綴；richart.tw 在允許清單內、其他網域仍拒絕；richart.tw 兩頁連到的優惠細則頁都被收集、同一則細則只下載一次；約定條款 PDF 照原檔存；更新模式對新類別有效（內容沒變不重寫、下架搬到 `_meta/removed/`）；不開更新模式時既有測試全綠。
- 先例：下載腳本現有的卡片頁、權益子頁、下載區與更新模式的子行程測試。
- 實機（主對話執行，排在 C 線與增量更新 ticket 11 之後）：下載 → 起草題目給使用者審 → 新基準 eval → 匯入 → eval → 判讀與搞混實例清單。

## Out of Scope

- 改進回答方式（在文件或 chunk 標卡別、改查詢的提示詞等）：看量測結果另開 spec（grill Q9）。
- 「Richart 金融卡約定事項」：richart.tw 上只有文字、沒有連結，找不到 PDF。
- 其他銀行的卡片。
- mkpcard 活動重新分類：主內容沒寫適用卡別的活動維持原狀，不額外標註（grill Q19）。
- 約定條款頁上指向悠遊卡公司（外部網域）的條款。
- 官網卡片頁內連到的泛用優惠頁與重要公告頁（盤點時各 5 個，未取）。
- 改下載資料夾的名稱。
