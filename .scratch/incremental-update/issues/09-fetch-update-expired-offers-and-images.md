# 09: 更新模式：活動重新判斷過期，活動圖片跟著活動走

**What to build:** 更新模式下，每個已有活動文件的活動都重新判斷是否過期（現有規則），過期的搬到 `DIR/_meta/removed/<日期>/`，清單記「過期移除」。活動過期或下架時，它的主視覺圖片也搬走（共用同一張圖的活動都過期或下架才搬）；名額少於 8 個時才從後面的活動補（spec「下載腳本：更新模式」的活動圖片與過期判斷，grill Q18、Q26、Q27）。

**Blocked by:** 07、08

**Status:** resolved

- [x] 已有活動文件的活動過期：活動文件與它的 `_meta` 檔案搬走，清單記「過期移除」；同一次既內容變更又過期的，也記「過期移除」。
- [x] 只有原始 HTML、沒有活動文件的活動：存檔 HTML 讀出的期間已過期時記「過期略過」，不請求詳情頁、不轉檔；沒有過期或期間不明時當成新增轉檔（07 的規則）。
- [x] 活動列表沒有成功取得：這次不判斷活動過期，也不判斷活動圖片下架。
- [x] 圖片的去留在活動的過期、下架與內容變更都處理完之後算：沒有任何一個「活動文件仍在」的活動的存檔 HTML 指向的圖片，搬到 `DIR/_meta/removed/<日期>/<圖片資料夾>/`。驗收三種情況：共用同一張圖的兩個活動只過期一個時圖片保留、兩個都過期時搬走；活動改版換了主視覺網址時舊圖搬走。
- [x] 名額照 spec 的算法：「活動文件仍在」的活動的主視覺網址去除重複後，圖片檔在本地存在的或副檔名不支援的各佔一個，下載失敗沒有留檔的不佔。只在名額少於 8 個時補：主視覺網址變了的仍有效活動排在最前面，其餘依活動被找到的順序，從「活動文件確實存在、有主視覺、主視覺網址還沒有佔名額」的活動補，補到 8 個或沒有候選為止（候選不足時報告寫明）；新出現在前面的活動不擠掉現有的圖片。
- [x] 下載腳本模組說明的已知極限改寫：「已存在的活動不重新判斷是否過期」「要刪 `_meta/html` 才會重新下載」改成區分有沒有開更新模式的說法。
- [x] 仍有效、主視覺網址沒變、已有圖片的活動：不重新請求它的圖片，位元組與修改時間不變。
- [x] 仍有效、主視覺網址變了的活動：舊圖搬走，新的主視覺照補名額規則下載，排在其他候選之前。
- [x] 測試沿用假 HTTP server；現有測試全綠。

## Comments

### 實作結果（2026-11-02）

更新模式下，已有活動文件的活動重新判斷期間，過期的連同 `_meta/html`、`_meta/print` 搬到 `DIR/_meta/removed/<日期>/`，清單記「過期移除」；活動圖片在活動都處理完之後，把沒有任何「活動文件仍在」的活動指向的圖片搬到 `DIR/_meta/removed/<日期>/offer_images/`（清單記「下架」），名額少於 8 個時才補，主視覺網址變了的排最前面。07 回報的「新頁面期間已過期仍記內容變更」已改成「過期移除」。

- `scripts/fetch_taishin.py`：`RESULT_EXPIRED_REMOVED`；`web_page_refresher` 加 `inspect`（活動頁用 `check_offer_period`，過期時拋 `SkipDocument`，檔案不動）；`fetch_document` 接住它並呼叫 `move_removed`（加 `result`、`reason` 參數）；`live_banners`／`banner_of`／`collect_banners_to_fill`／`remove_unreferenced_images`；`Run.previous_banners`；模組說明（更新模式、已知極限）、`--update` 說明與 README 同步。
- `scripts/test_fetch_taishin.py`：`UpdateModeExpiredOfferTests`（2 個）、`UpdateModeOfferImageTests`（11 個）；`serve_activities`、`image_requests` 從 `OfferImageTests` 移到 `ScriptTestCase` 共用。縫沿用下載腳本子行程加假 HTTP server、假 Chrome、假 LibreOffice；沒有過期但頁面不變的情況，用子行程的 `sitecustomize` 把 `date.today()` 往後撥兩天。
- 紅綠：過期移除 2 個測試、圖片搬走 1 個測試各先紅後綠；圖片名額 4 個測試中，新活動在前面不擠掉、主視覺網址變了的排前面、候選不足的報告 3 個先紅後綠，「過期騰出的名額由下一個活動補」第一次就綠（舊的取前 8 個規則剛好給出同樣結果）。共用圖片、列表少了、沒變不重新請求、列表失敗不判斷、不支援格式佔名額與下載失敗不佔名額共 5 個測試，在同一輪實作後才執行，第一次就綠。主視覺網址變了的搬舊圖與下載新圖：測試第一版紅燈，原因是測資只換主視覺、主內容區沒變（見範圍外發現），改成主內容區也變後綠，實作沒有為此改動。

ASSUMPTION：

- 過期活動不轉檔：期間在比對與轉檔之前判斷，所以搬走的是舊版本的文件與存檔 HTML，這次取得的新頁面不存檔；下次執行時這個活動沒有文件也沒有存檔，照一般流程記「過期略過」並存下原始 HTML。「過期移除」清單紀錄的網址是活動詳情頁網址，period 是這次讀到的期間，其餘欄位取搬走的文件。
- 取得頁面失敗的活動（清單記「失敗」）原封不動，不用存檔的期間補判斷過期。
- 活動圖片的「活動文件仍在」＝這次活動列表裡有、活動 PDF 與存檔的原始 HTML 都在本地。搬移失敗而文件還留著的活動、以及已不在列表的活動，都不算在內（前者的圖片會被搬走，下次執行再處理）。
- 「主視覺網址變了」＝活動在重新取得之前有文件與存檔 HTML，而存檔裡的主視覺網址和重新取得後不同（含原本沒有主視覺、現在有）。
- 補名額只選一次：補上的圖片下載失敗時，不再順延下一個候選，下次執行再補。圖片檔名的雜湊後綴（同名衝突時）依活動「仍在」的全部主視覺算，和第一次下載依前 8 個算，兩者在同名衝突時可能不同，極端少見，沒有處理。
- 「下架」的圖片清單紀錄網址是空字串，原因寫「沒有任何仍在的活動使用這張圖片」。
- 補不滿 8 個時，stdout 印「活動圖片名額 N/8，沒有更多候選」。

範圍外發現：

- 主視覺（`div.banner-image`）在詳情頁主內容區（class 含 `page-content`）的外面，2026-11-02 看一份本機存檔的樣本確認。07 的比對只看主內容區，所以只換主視覺、主內容區沒變的活動，存檔的原始 HTML 不會換，主視覺網址的變動偵測不到，舊圖不會搬、新圖不會補。要偵測的話，比對要加上主視覺網址（會讓 07 的「主內容區以外的差異不算變更」多一個例外），這是使用者的決定，沒有動。已寫進模組說明的已知極限與 README。
