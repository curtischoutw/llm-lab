# 09: 更新模式：活動重新判斷過期，活動圖片跟著活動走

**What to build:** 更新模式下，每個已有活動文件的活動都重新判斷是否過期（現有規則），過期的搬到 `DIR/_meta/removed/<日期>/`，清單記「過期移除」。活動過期或下架時，它的主視覺圖片也搬走（共用同一張圖的活動都過期或下架才搬）；名額少於 8 個時才從後面的活動補（spec「下載腳本：更新模式」的活動圖片與過期判斷，grill Q18、Q26、Q27）。

**Blocked by:** 07、08

**Status:** ready-for-agent

- [ ] 已有活動文件的活動過期：活動文件與它的 `_meta` 檔案搬走，清單記「過期移除」；同一次既內容變更又過期的，也記「過期移除」。
- [ ] 只有原始 HTML、沒有活動文件的活動：存檔 HTML 讀出的期間已過期時記「過期略過」，不請求詳情頁、不轉檔；沒有過期或期間不明時當成新增轉檔（07 的規則）。
- [ ] 活動列表沒有成功取得：這次不判斷活動過期，也不判斷活動圖片下架。
- [ ] 圖片的去留在活動的過期、下架與內容變更都處理完之後算：沒有任何一個「活動文件仍在」的活動的存檔 HTML 指向的圖片，搬到 `DIR/_meta/removed/<日期>/<圖片資料夾>/`。驗收三種情況：共用同一張圖的兩個活動只過期一個時圖片保留、兩個都過期時搬走；活動改版換了主視覺網址時舊圖搬走。
- [ ] 名額照 spec 的算法：「活動文件仍在」的活動的主視覺網址去除重複後，圖片檔在本地存在的或副檔名不支援的各佔一個，下載失敗沒有留檔的不佔。只在名額少於 8 個時補：主視覺網址變了的仍有效活動排在最前面，其餘依活動被找到的順序，從「活動文件確實存在、有主視覺、主視覺網址還沒有佔名額」的活動補，補到 8 個或沒有候選為止（候選不足時報告寫明）；新出現在前面的活動不擠掉現有的圖片。
- [ ] 下載腳本模組說明的已知極限改寫：「已存在的活動不重新判斷是否過期」「要刪 `_meta/html` 才會重新下載」改成區分有沒有開更新模式的說法。
- [ ] 仍有效、主視覺網址沒變、已有圖片的活動：不重新請求它的圖片，位元組與修改時間不變。
- [ ] 仍有效、主視覺網址變了的活動：舊圖搬走，新的主視覺照補名額規則下載，排在其他候選之前。
- [ ] 測試沿用假 HTTP server；現有測試全綠。
