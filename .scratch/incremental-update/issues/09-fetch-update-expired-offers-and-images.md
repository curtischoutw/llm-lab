# 09: 更新模式：活動重新判斷過期，活動圖片跟著活動走

**What to build:** 更新模式下，每個活動都重新判斷是否過期（現有規則），過期的搬到 `_meta/removed/<日期>/`，清單記「過期移除」。活動過期或下架時，它的主視覺圖片也搬走，再依活動被找到的順序，從後面有主視覺的活動補上，維持 8 個；仍然有效的活動，圖片不換（spec「下載腳本：更新模式」的活動圖片）。

**Blocked by:** 08

**Status:** ready-for-agent

- [ ] 已下載的活動過期：活動文件搬走，清單記「過期移除」。
- [ ] 過期或下架活動的圖片搬走。
- [ ] 只在圖片總數少於 8 個時補：依活動被找到的順序，從「活動文件確實存在、有主視覺、還沒有圖片」的活動補，補到 8 個或沒有候選為止（候選不足時報告寫明）。新出現在前面的活動不擠掉現有的圖片。
- [ ] 仍有效、已有圖片的活動：不重新請求它的圖片，位元組與修改時間不變。
- [ ] 測試沿用假 HTTP server；現有測試全綠。
