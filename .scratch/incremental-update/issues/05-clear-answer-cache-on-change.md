# 05: 知識庫有改動時清掉答案快取

**What to build:** 每份文件處理完，只要那份文件的處理對知識庫做了寫入或刪除（不論最後成功或失敗，含替換失敗後的清除與 prune 的刪除），就立刻清掉 LLM 快取裡所有查詢答案的項目，保留查詢關鍵字與匯入用的抽取快取；之後同一題會用新的知識庫重新回答。知識庫沒有改動的文件不觸發。報告寫出這次清掉的筆數（spec「匯入端：答案快取」，grill Q4、Q25）。

**Blocked by:** 01、02、04

**Status:** ready-for-agent

- [ ] 新增、替換、prune 刪除之後：先前問過的題目再問一次，會重新呼叫假 LLM 生成答案（從假 server 的請求紀錄觀察）。
- [ ] 替換失敗（寫了一半的內容已清除）與新文件失敗之後：同樣清掉答案快取。判準照 spec「詞彙」：解析完成、開始寫進 LightRAG 之後失敗的算有改動；解析階段就失敗的（例如假 mineru 回錯誤）不清。
- [ ] 沒變、共用版本的新增或刪除（知識庫沒有改動）：同一題再問仍命中答案快取。
- [ ] 清除在每份文件處理完時發生，不等整批結束：用外部看得到的方式驗證（例如一批兩份，第一份處理完、第二份處理中時讓假 server 停住並結束子行程，再問先前的題目會重新生成答案）。
- [ ] 關鍵字快取保留：同一題再問時，不重新呼叫抽關鍵字。
- [ ] 抽取快取保留：prune 刪掉一份文件後再匯入同一份，不重新呼叫實體抽取（從假 server 的請求紀錄觀察）。
- [ ] 只清查詢答案的項目，不用 LightRAG 清全部快取的功能。
- [ ] 報告寫出清掉的筆數；CLI 與 Python API 行為相同。
- [ ] README 寫明這個行為；現有測試全綠。
