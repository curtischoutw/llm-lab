# 04: 來源已不在：只列出，加 `--prune` 才刪

**What to build:** 使用者執行 `ingest <資料夾>` 時，之前從這個資料夾匯入、現在檔案不在的文件，列在報告的「來源已不在（未刪）」；加 `--prune` 才從知識庫刪掉，而且只刪之前從這個資料夾匯入的，報告記「已刪除」。Python API 指定來源資料夾與 prune 時行為相同（spec「匯入端：替換與移除」「匯入端：介面」）。

**Blocked by:** 01、02（刪除前查共用版本、刪除時保留抽取快取，和 02 刪舊版本用同一段邏輯，沿用 02 的實作）

**Status:** ready-for-agent

- [ ] 不加 prune：來源已不在（以檔案系統判斷）的文件只列出路徑，知識庫與對照表不變；沒有其他失敗時結束碼 0。
- [ ] Python API 指定了來源資料夾時，對照表記的來源資料夾是指定的資料夾；沒指定時是檔案所在的資料夾（spec「匯入端：對照表」）。
- [ ] 加 prune：逐一刪除（保留 LLM 抽取快取），移除對照表那一筆，報告記「已刪除」；每份文件只歸一類，不再算「來源已不在」。
- [ ] 只處理來源資料夾等於這次資料夾的紀錄；其他資料夾匯入的文件不受影響。
- [ ] 刪除前先查對照表：還有別的路徑指向同一個文件 ID 時，不刪知識庫的內容，只移除這個路徑的那一筆，報告仍記「已刪除」。
- [ ] 資料夾不存在或已沒有支援的文件時：CLI 照現行規則以結束碼 2 結束，不做移除（grill Q24）；Python API 在來源資料夾不存在、或文件清單是空的而給了 prune 時拋使用錯誤。
- [ ] 匯入單一檔案時不檢查移除；單一檔案加 `--prune` 以結束碼 2 結束並說明原因；Python API 沒有來源資料夾卻給 prune 時拋使用錯誤。
- [ ] 刪除失敗：報告記成失敗並寫出原因，結束碼 1。
- [ ] README 寫明 `--prune` 的行為與建議的使用順序（先不加、看清單、再加）；現有測試全綠。
