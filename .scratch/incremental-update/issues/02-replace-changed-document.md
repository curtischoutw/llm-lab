# 02: 替換變更的文件：先匯入新版本，成功後刪舊版本

**What to build:** 同一個路徑上的文件內容改了，使用者再次 `ingest` 後，知識庫裡只剩新版本，查詢不會再檢索到舊內容；報告列為「替換」。新版本匯入失敗時，舊版本留著，報告記成失敗並說明舊版本仍在（spec「匯入端：替換與移除」）。

**Blocked by:** 01

**Status:** ready-for-agent

- [ ] 對照表裡有這個路徑、內容變了：先匯入新版本，成功後刪除舊版本（保留 LLM 抽取快取），更新對照表；報告列為「替換」。
- [ ] 替換後查詢只看得到新版本的內容（用假 server 觀察送給 LLM 的 context）。
- [ ] 新版本匯入失敗（含圖、表、公式描述失敗而文字已寫入的情況）：刪掉新版本已寫進知識庫的部分，舊版本與對照表不變，報告記成失敗並說明舊版本仍在，結束碼 1。
- [ ] 刪除舊版本失敗：報告記成失敗，訊息寫出新舊兩個文件 ID，結束碼 1。
- [ ] 替換中斷後（新版本已完整匯入、舊版本沒刪、對照表仍指向舊 ID）再次 ingest：補刪舊 ID，報告記為「替換」。
- [ ] 對照表記的 ID 已不在知識庫：不刪任何東西，只更新對照表。
- [ ] 刪舊版本前先查對照表：還有別的路徑指向同一個 ID 時，不刪知識庫的內容，只改寫這個路徑的那一筆。
- [ ] 匯入單一檔案時也會替換。
- [ ] CLI 與 Python API 行為相同；現有測試全綠。
